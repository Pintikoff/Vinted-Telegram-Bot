# Vinted Deal Bot — Design

## Контекст и цель

Бот для личного использования на домашнем сервере (хомлаб), который отслеживает заданные
товарные позиции на Vinted (например, `carhartt detroit jacket`, `carhartt active jacket`,
`dickies polo`), определяет, когда новый лот продаётся заметно дешевле рыночной цены, и
присылает уведомление в Telegram — чтобы успеть купить товар для перепродажи.

Домен: `vinted.de` (Германия).

## Критерий «выгодного» товара

Рыночная цена модели = **медиана цен всех активных лотов**, которые возвращает поисковый
запрос этой модели на Vinted, пересчитываемая заново при каждой проверке (без накопления
истории).

Товар считается выгодным, если его цена ниже медианы на величину порога (по умолчанию 30%,
настраивается пользователем через Telegram, см. ниже). Размер лота в расчёт медианы не
влияет — медиана считается по всей модели целиком, без разбивки по размерам. Стоимость
доставки в сравнении не учитывается, только цена товара.

Если по запросу найдено менее 5 активных лотов — модель пропускается в этом цикле проверки
(медиана на малой выборке ненадёжна).

## Отслеживаемые модели — не категории, а конкретные позиции

Вместо широких категорий («Carhartt», «Dickies») бот ведёт список узких поисковых запросов,
каждый соответствующий одной конкретной модели (например, `"carhartt detroit jacket"`,
`"carhartt active jacket"`). Это гарантирует, что при расчёте медианы разные модели не
смешиваются между собой. Список управляется владельцем бота через команды в Telegram (см.
раздел «Telegram-бот»), не через конфиг-файл.

## Архитектура

Один Python-процесс в Docker-контейнере. Внутри процесса работают параллельно (через
`asyncio`) два воркера:

1. **Scheduler** — раз в `CHECK_INTERVAL_SECONDS` (по умолчанию 900 с / 15 мин) проверяет
   все отслеживаемые модели.
2. **Telegram bot** (long polling) — слушает команды владельца для управления списком
   моделей и порогом.

Оба воркера используют общее хранилище — один файл SQLite в volume контейнера.

```
┌─────────────────────────────────────────────┐
│         Scheduler (каждые 15 мин)             │
│                                               │
│  1. Прочитать tracked_models из SQLite        │
│  2. Для каждой модели:                       │
│     - запрос к Vinted API (search_text)      │
│     - медиана цены по активным лотам         │
│     - если < 5 лотов → пропустить            │
│     - найти лоты, которых нет в seen_items   │
│     - цена ≤ медиана * (1 - threshold%) →     │
│       сигнал                                 │
│  3. Отправить сигналы в Telegram             │
│  4. Записать все увиденные лоты в seen_items  │
└─────────────────────────────────────────────┘
          ▲                           │
          │ /add /remove /list        │ алерты с фото + ссылкой
          │ /threshold /status        │
          │                           ▼
┌─────────────────────┐      ┌──────────────────┐
│ Telegram bot          │      │   Чат владельца   │
│ (long polling)        │◄─────┤                   │
└─────────────────────┘      └──────────────────┘
```

## Хранилище (SQLite)

**`tracked_models`**
- `id` (PK)
- `search_text` — текст поискового запроса, например `"carhartt detroit jacket"`
- `added_at`

**`seen_items`** — для дедупликации уведомлений
- `item_id` (PK) — ID лота на Vinted
- `model_id` (FK → tracked_models.id)
- `first_seen_at`

Записи старше 30 дней из `seen_items` периодически удаляются (лоты на Vinted обычно не
живут так долго, таблица не должна расти бесконечно).

**`settings`** — key-value, одна запись управляется пользователем
- `threshold_percent` — порог скидки от медианы, по умолчанию `30`

Минимальное количество лотов для надёжной медианы (5) — захардкоженная константа в коде,
не настройка пользователя.

## Клиент Vinted API

Собственный минимальный HTTP-клиент (без сторонних библиотек типа `pyVinted`), единственный
модуль в проекте, который знает про специфику Vinted:

1. **Bootstrap сессии** — GET на `https://www.vinted.de/` для получения сессионной cookie.
   Сессия кешируется в памяти процесса и обновляется заново, если API возвращает 401/403.
2. **Поиск лотов** — GET на `https://www.vinted.de/api/v2/catalog/items` с параметрами
   `search_text`, `order=newest_first`, `per_page=96`, с cookie из шага 1.
3. **Парсинг ответа** — извлекаются `id`, `title`, `price.amount`, `size_title`, `photo.url`,
   `url` (ссылка на лот) из JSON.
4. **Retry** — до 3 повторов с задержкой при сетевой ошибке/не-200 статусе, затем пропуск
   модели в этом цикле проверки (ошибка одной модели не должна останавливать весь цикл).

## Telegram-бот

Доступ к командам ограничен одним Telegram `user_id` (владелец), задаётся в конфиге.
Сообщения от остальных пользователей игнорируются.

| Команда | Действие |
|---|---|
| `/add <текст запроса>` | добавить модель в отслеживание |
| `/remove <номер или текст>` | удалить модель из списка |
| `/list` | показать все отслеживаемые модели с их id |
| `/threshold [значение]` | без аргумента — показать текущий порог (%); с аргументом — установить новый |
| `/status` | время последней успешной проверки, количество отслеживаемых моделей |

**Формат уведомления о выгодном лоте** (текст + фото лота):

```
🔥 Carhartt Detroit Jacket — -42% от медианы

Цена: 18 €  (медиана: 31 €, по 23 лотам)
Размер: M
https://www.vinted.de/items/xxxxx
```

## Обработка ошибок и устойчивость

- **Сбой запроса к Vinted для одной модели** — логируется, модель пропускается в этом
  цикле, остальные модели проверяются как обычно.
- **Все модели подряд проваливаются несколько циклов** — присылается одно
  предупреждение в Telegram ("Vinted недоступен уже N циклов"), чтобы проблема не
  осталась незамеченной без постоянного чтения логов.
- **Сбой отправки уведомления в Telegram** — логируется, лот не записывается в
  `seen_items`, поэтому уведомление о нём будет повторно отправлено в следующем цикле
  (сигнал не теряется).
- **Падение контейнера** — Docker перезапускает процесс (`restart: unless-stopped`);
  состояние (модели, порог, seen_items) не теряется, так как SQLite лежит на volume.

## Конфигурация и деплой

Переменные окружения (`.env`):
- `TELEGRAM_BOT_TOKEN`
- `TELEGRAM_OWNER_ID`
- `VINTED_DOMAIN` (по умолчанию `vinted.de`)
- `CHECK_INTERVAL_SECONDS` (по умолчанию `900`)

`docker-compose.yml`: один сервис, volume под файл SQLite, `restart: unless-stopped`.

## Вне скоупа (не делаем в этой версии)

- Сравнение цен между странами/доменами Vinted.
- Учёт состояния товара (новое с биркой / б/у) при расчёте медианы.
- Учёт стоимости доставки.
- Разбивка медианы по размерам.
- Web-дашборд — всё управление только через Telegram-команды.
